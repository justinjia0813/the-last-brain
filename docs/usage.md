# 使用与隐私说明

The Last Brain 是 Obsidian 的只读问答插件。它在本地检索当前笔记库中的 Markdown 笔记，把选中的片段交给你配置的模型服务，并保存对话、来源快照和经你确认的记忆。

## 安装

需要 Obsidian 1.11.4 或更新版本。

1. 从 [GitHub 最新版](https://github.com/justinjia0813/the-last-brain/releases/latest)下载并解压发布包。
2. 将其中的 `the-last-brain` 文件夹放进目标笔记库的 `.obsidian/plugins/` 目录。安装目录内应包含 `main.js`、`manifest.json` 和 `styles.css`。
3. 在 Obsidian「设置 → 第三方插件」启用 **The Last Brain**。如果插件列表没有更新，可重启 Obsidian。
4. 在插件设置中配置模型服务，并按需开启向模型服务发送上下文。
5. 点击左侧聊天图标，或运行「The Last Brain: 打开只读问答」命令。

社区目录审核和版本显示可能晚于 GitHub 发布。

## 配置模型

打开插件设置中的模型配置，选择服务，填写接口地址、模型名称和密钥，然后保存并使用。插件兼容 OpenAI 风格的聊天接口，例如：

- 云端服务：`https://api.openai.com/v1`
- 本地服务：`http://localhost:11434/v1`

地址和可用模型取决于所选服务。插件不内置或捆绑模型额度。你也可以主动测试连接；测试请求只发送固定的合成问候，不发送笔记内容。服务商可能要求账户、密钥或付费。

## 问答与来源

提出包含项目、公司或主题名称的具体问题。插件会在本地检索笔记，再将问题和选中的片段发送给模型。回答下方的来源片段保留当时引用的文本、路径和笔记修改时间。点击路径可打开仍存在的笔记；来源笔记已删除时只会提示，不会重建文件。

引用编号由模型生成，请对照显示的来源片段检查。没有来源支持的回答不应视为笔记库已证实的结论。

对话会自动保存在本地，可新建、切换或删除。删除对话会同时删除该对话生成的记忆，并在操作前要求确认。

## 记忆

问答结束后，可请求整理记忆草稿。草稿尝试区分证据、推断、未知和建议，并区分用户偏好与笔记中的主张；这是给模型的提示，不能保证每次都严格遵循。请检查并编辑草稿。

记忆只有在你确认后才会按相关性加入后续请求。已有记忆不会随笔记变化自动更新，可在「记忆」页编辑或删除。记忆草稿基于最近最多 7 条对话及相关笔记片段，不是对无限长对话的完整总结。

## 读取、发送与保存

插件只读取当前 vault 中可读、未排除的 Markdown 正文和路径；不会解析附件或抓取外部链接。检索在本地逐篇扫描符合条件的笔记，复用 Obsidian 读取缓存。它不会将整个 vault 上传给模型；每次请求只发送检索选出的片段、问题、有限的近期对话和相关已确认记忆。

只有点击「发送」、「整理为记忆草稿」或「测试连接」才会发起模型请求。不会后台扫描上报，也不会自动生成记忆。问答和记忆请求会向你配置的服务发送问题、近期对话、命中的笔记片段和相关已确认记忆。测试连接只发送固定问候。插件只调用你配置的模型接口，不含遥测、广告或自动更新机制。

排除目录在本地读取前生效，也会阻止相关记忆参与之后的请求。历史消息中已经生成的回答仍可能包含此前发送的内容；更改排除设置不能撤回已经发送的数据。若需要清理旧内容，请新建对话并删除不应保留的旧对话。

笔记和附件保持只读：插件不创建、编辑、删除或移动它们，不执行命令，也不给模型任何文件操作工具。模型输出以安全文本显示，支持标题、强调和来源引用，不渲染模型生成的网页、图片或可执行代码。

对话、来源文本快照、设置和记忆保存在每个 vault 各自的 `.obsidian/plugins/the-last-brain/data.json`。若同步方案包含插件目录，这些数据也可能被同步。卸载前请备份该文件。模型密钥保存在 Obsidian 自带的密钥存储中，不写入聊天数据文件。对话和记忆文件没有额外加密。

## 当前范围与限制

| 范围 | 当前行为 |
| --- | --- |
| 笔记读取 | Markdown 正文和路径；不解析附件，不抓取外部链接 |
| 检索 | 中英文关键词与正文分块；默认最多 6 个来源，每篇笔记取最相关的一段 |
| 覆盖范围 | 检查全部未排除且可读取的 Markdown 笔记；无单篇或整库字节截断 |
| 上下文预算 | 笔记片段总上限可选 8,000、16,000 或 32,000 字符，默认 16,000；每段最多约 1,200 字符 |
| 对话上下文 | 当前问题最多 12,000 字符；最多 7 条历史消息，合计约 8,000 字符；完整历史保存在本地 |
| 记忆 | 每次最多 4 条相关已确认记忆，正文合计约 6,000 字符 |
| 请求等待 | 90 秒上限；停止等待或超时不保证服务端停止处理，重试可能额外计费 |
| 已验证环境 | macOS 桌面版 Obsidian 的合成模型流程；真实服务质量和移动端行为尚未验证 |

关键词检索不保证同义词召回，也不提供语义或向量检索。选中的片段有限，因此不能声称模型完整阅读了整个 vault。首版不支持附件解析、自动记忆或笔记编辑。

## 开发与验证

```sh
npm ci
npm run check
```

`npm run check` 运行检索、请求预算、来源隔离、记忆筛选、响应校验、历史恢复和损坏数据保护检查，并构建插件。构建生成根目录 `main.js` 和 `release/the-last-brain/` 安装目录；运行时依赖 Obsidian。

原生界面检查使用合成数据和本机合成模型服务。详细结果见[验收记录](validation.md)。开发接口依据[Obsidian 官方示例插件](https://github.com/obsidianmd/obsidian-sample-plugin)和官方类型定义；网络请求采用 Obsidian 的 `requestUrl`。
